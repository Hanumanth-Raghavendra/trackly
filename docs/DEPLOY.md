# Deploying Trackly for free

Everything here runs on free plans with **no credit card**. Total time: about 30 minutes, most of
it waiting for the first builds.

| Piece | Where | Free plan limits that matter (checked October 2026) |
|---|---|---|
| Web app | Vercel Hobby | Free for personal, non-commercial projects |
| core-api + insights | Render, 2 free web services | Sleep after 15 min without traffic, ~1 min to wake; 750 instance hours a month per workspace |
| Database | Neon Free | 100 CU-hours of compute and 1 GB storage per project; scales to zero after 5 min idle |
| CI, Android builds, reminder cron | GitHub Actions | Free for public repositories |

> **Why it can't cost you money:** none of these accounts has a payment method, so when a limit is
> reached the service pauses until next month instead of billing you. Keep it that way: **never add
> a card to Render, Vercel or Neon** for this project. (Render's own docs: without a payment method
> it suspends free services instead of charging.)

The order below matters: Vercel first (so you know its URL), then the database, then Render.

---

## 1. Make `main` the default branch

GitHub → your `trackly` repo → **Settings** → **General** → **Default branch** → switch to
**`main`** → **Update**. (Render and Vercel deploy from `main`.)

## 2. Vercel: the web app

1. Go to <https://vercel.com/signup> → **Continue with GitHub** → choose the **Hobby** plan.
2. **Add New… → Project** → find `trackly` → **Import**.
3. On the configure screen:
   - **Root Directory** → **Edit** → select `apps/web` → **Continue**.
   - Framework Preset: **Vite** (detected automatically).
   - **Environment Variables** → add one:

     | Key | Value |
     |---|---|
     | `VITE_SOCKET_URL` | `https://trackly-insights.onrender.com` |

     (Live sync uses WebSockets, which can't go through Vercel's proxy, so the browser connects to
     the insights service directly.)
4. **Deploy**. It finishes in about a minute. The app loads, but sign-in won't work until steps 3–4
   are done.
5. Optional, a nicer URL: project → **Settings** → **Domains** → edit the `.vercel.app` domain,
   for example to `trackly-hr.vercel.app`.
6. **Write down your final URL**, for example `https://trackly-hr.vercel.app`. You need it in step 4.

## 3. Neon: the database

1. Go to <https://neon.com> → **Sign up** → **Continue with GitHub**.
2. Create a project:
   - Name: `trackly`
   - Region: **AWS Asia Pacific (Singapore)** (closest to the Render region and to India)
3. On the project dashboard click **Connect**. In the dialog:
   - Turn **Connection pooling off** (Trackly keeps its own small connection pools).
   - Copy the connection string. It looks like
     `postgresql://neondb_owner:xxxx@ep-xxxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require`

You don't create any tables: core-api (Flyway) and insights create their own schemas on first start.

## 4. Render: the two backends

1. Go to <https://render.com> → **Get Started** → **GitHub**. Skip any billing prompt.
2. In the dashboard: **New** → **Blueprint**.
3. Connect the `Hanumanth-Raghavendra/trackly` repository, branch **`main`**. Render reads
   `render.yaml` and shows an env group `trackly-shared` and two web services: `trackly-core-api`
   and `trackly-insights`, both on the **Free** plan in **Singapore**.
4. It asks for two values:

   | Key | Value |
   |---|---|
   | `DATABASE_URL` | the Neon connection string from step 3 |
   | `CORS_ALLOWED_ORIGINS` | your Vercel URL from step 2, e.g. `https://trackly-hr.vercel.app` (no trailing slash; separate several with commas) |

   The JWT signing key and the service-to-service token are generated by Render; you never see
   or type them.
5. **Apply** / **Deploy Blueprint**. The first builds take 5–10 minutes (core-api compiles Java
   and prepares a class-data archive for faster cold starts).
6. When both show **Live**, check their URLs at the top of each service page:
   - `https://trackly-core-api.onrender.com/actuator/health` should show `{"status":"UP",…}`
   - `https://trackly-insights.onrender.com/health` should show `{"status":"ok",…}`

### If Render gave a service a different URL

Service names are global on Render. If one was taken, Render adds a suffix, for example
`trackly-core-api-x7k2.onrender.com`. Then update these 4 places with your real URLs:

| Where | What |
|---|---|
| `apps/web/vercel.json` in the repo | every `destination` URL (find and replace the host; commit and push, and Vercel redeploys) |
| Vercel → project → Settings → Environment Variables | `VITE_SOCKET_URL` = your insights URL, then **Redeploy** |
| Render → `trackly-core-api` → Environment | `INSIGHTS_URL` = your insights URL |
| GitHub → repo → Settings → Secrets and variables → Actions → **Variables** | `MOBILE_API_URL`, `MOBILE_INSIGHTS_URL`, `INSIGHTS_URL` (used by the Android and reminder workflows) |

## 5. Try it

Open your Vercel URL → **Try the live demo**. The first visit after a quiet spell takes about a
minute while the free servers wake up. The landing page starts waking them as soon as it loads,
and the app shows a "waking up" note instead of a frozen screen. After that it's fast.

From now on: **push to `main` → CI runs → if it's green, Render deploys** (`autoDeployTrigger:
checksPass` in `render.yaml`), and Vercel deploys the web app on every push.

## Optional extras (all free)

### Habit reminders and morning plans while the app is closed

The insights service sends reminders while it's awake. To wake it once an hour, the
`Reminders` GitHub workflow calls it with a secret token:

1. Render → **Env Groups** → `trackly-shared` → `INTERNAL_SERVICE_TOKEN` → reveal → copy.
2. GitHub → repo → **Settings** → **Secrets and variables** → **Actions** → **New repository
   secret**: name `INSIGHTS_SERVICE_TOKEN`, value = what you copied.
3. Actions tab → **Reminders** → **Run workflow** once to test (it should end green).

Cost check: about 24 short wake-ups a day, which stays well inside Render's 750 hours and Neon's
100 CU-hours. GitHub pauses scheduled workflows in repos with no commits for 60 days; any push
re-enables it. The Android app doesn't need this: it schedules habit reminders on the phone itself.

### Browser push notifications

1. Generate a key pair. In a terminal, in the `services/insights` folder of your clone (for example
   `C:\Users\<you>\trackly\services\insights`), run:

   ```bash
   npx web-push generate-vapid-keys
   ```
2. Render → `trackly-insights` → **Environment** → add:

   | Key | Value |
   |---|---|
   | `VAPID_PUBLIC_KEY` | the "Public Key" line |
   | `VAPID_PRIVATE_KEY` | the "Private Key" line |
   | `VAPID_SUBJECT` | `mailto:` followed by your email |

3. Save (the service restarts). In the app: **Settings** → **Notifications** → turn on push.

### AI weekly summaries and "break this task down"

Trackly works fully without AI: the coach cards and weekly review are rule-based. To add AI
writing on top, using **Google Gemini's free tier**:

1. <https://aistudio.google.com> → sign in → **Get API key** → **Create API key**.
   Use it in a Google Cloud project **without billing enabled**: that's what keeps it on the free
   tier (requests over the free quota are refused, not charged).
2. Render → `trackly-insights` → **Environment** → add `AI_PROVIDER` = `gemini` and
   `AI_API_KEY` = your key.

Any OpenAI-compatible API also works (Groq's free tier, OpenRouter, a local Ollama, or a paid
OpenAI account later): set `AI_PROVIDER=openai`, `AI_BASE_URL`, `AI_API_KEY` and `AI_MODEL`.
Anthropic Claude: `AI_PROVIDER=anthropic` + `AI_API_KEY` (paid). Switching providers is
configuration only, no code changes. Each user is limited to 30 AI requests an hour.

### The Android app

See [MOBILE.md](MOBILE.md): GitHub builds the APK for you (Actions → **Android app** →
**Run workflow**).

## Troubleshooting

| Symptom | Fix |
|---|---|
| "Can't reach Trackly" right after deploying | Wait a minute: the free services are waking. Open both health URLs from step 4.6 to wake them. |
| Sign-in fails with 403 | `CORS_ALLOWED_ORIGINS` on `trackly-core-api` doesn't exactly match your Vercel URL (check `https`, no trailing `/`). |
| Signed in, but nothing updates live across tabs | `VITE_SOCKET_URL` is missing or wrong in Vercel; redeploy after fixing. |
| Render build fails | Open the deploy logs. If it's the database, re-check `DATABASE_URL` (pooling off, ends with `sslmode=require…`). |
| Everything stopped near the end of a month | A free limit was reached (Render instance hours or Neon compute). It resumes on the 1st; check usage in each dashboard. |
